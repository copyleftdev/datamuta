Database migration that proves what it did.

Datamuta is an experimental Rust runtime. It seals a source snapshot to disk, publishes only the plan you approved by hash, commits a receipt with every partition, and checks the values that landed.

Experimental. Not for production data. PostgreSQL → PostgreSQL is the documented path.

Run the three-row example Source on GitHub

Capture a snapshot, then let the source go.

Datamuta reads a flat, typed snapshot in bounded pages. PostgreSQL capture blocks source writes until it finishes. After that, publication needs only the sealed spool and the destination; the source can be offline.

datamuta-stream capture --config config.json --spool snapshot --plan plan.json

Every field is assigned exactly once.

The mapping is explicit: copies, renames and lossless i32 → i64 widening. Unsupported conversions, nullable-to-required mappings and reordered identities are refused before any data moves.

mapping.json · version 1 · 4 fields

Data is sealed into partitions on disk.

Records are encoded into partitions of at most 256 rows and 1 MiB, bound by partition hashes and Merkle proofs. The spool has a hard budget: 256 MiB by default, 4 GiB at most.

snapshot/ · sealed manifest · partition hashes

Inspection grants nothing. The hash does.

Engines, endpoints, schemas, mapping, the implementation fingerprint and the snapshot are bound into one plan. run refuses to start without the exact hash you reviewed.

datamuta-stream run --plan plan.json --spool snapshot --approved-plan-sha256 HASH

Each partition commits with its own receipt.

A partition's records, receipt and cursor commit atomically in the destination. Resume reads that native evidence, and a timeout is never taken as proof of rollback.

datamuta-stream status --plan plan.json --spool snapshot

Progress is not correctness. Values are.

Verification reads what is stored in the destination and compares it with the transformed, authenticated spool. A clean exit or an intact receipt chain does not replace it.

datamuta-stream verify --plan plan.json --spool snapshot --out verification.json

Three rows, start to finish.

Two disposable PostgreSQL 17 containers on loopback ports 55432 and 55433, invented data, and the commands from the pipeline above. You need Docker Compose and Rust 1.99 or newer.

Replace HASH with the plan_sha256 that inspect prints, after you have read the plan.

Where it runs today.

Adapter code exists for four engines. Only PostgreSQL has a complete documented example; the others are laboratory profiles, and their presence is not a support promise.

EngineCapturePublishReadiness
PostgreSQLComplete documented example on a restricted PostgreSQL 17 profile. Still experimental.
MySQLLaboratory loopback profile, restricted InnoDB tables.
MongoDBLaboratory loopback replica set, restricted flat documents.
FirestoreLocal emulator only, prescribed flat collection and identity format.
